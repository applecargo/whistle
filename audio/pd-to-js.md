# Pd → JS 메시지

패치가 `[s 이름]`으로 보낸 것을 JS가 받을 수 있다. 엔진(pd4web 3.4.1)을 다시 빌드하지 않아도 된다.
**아직 앱에서는 쓰지 않는다**(받는 코드가 없음). 아래는 시험으로 확인한 동작과 쓰는 법이다(2026-11-24, 크로미움·Firefox).

## 확인한 것

- 오디오 랩에서 `[r probe-in]`을 받아 `[s probe-out]`, `[s probe-bang]`, `[s probe-list]`로 다시 내보내는 패치를 만들고,
  JS에서 `onFloatReceived`, `onBangReceived`, `onListReceived`로 받아 보니 모두 들어왔다.
- 예전에 "콜백이 오지 않는다"고 적었던 것은 시험 방법이 틀렸던 것이다.
  - 엔진은 출력이 스피커 쪽에 연결된 패치가 하나라도 있을 때만 돈다. 브라우저는 출력이 아무 데도 이어지지 않은 오디오 노드는 돌리지 않는다.
  - 그래서 슬롯을 하나도 안 띄운 상태에서는 Pd가 멈춰 있고, JS가 보낸 메시지도 대기열에 쌓여만 있다.
  - 예전 시험이 이 상태였다. 이번에도 처음엔 아무것도 안 오다가, 패치를 하나 띄우자 바로 다 왔다.
  - 게임에서는 소리가 나는 동안 항상 슬롯이 떠 있으니 문제가 안 된다.

## 메시지가 오는 길 (pd4web C++ 소스로 확인)

- Pd는 오디오 스레드에서 돈다. `[s 이름]`이 JS가 등록한 이름으로 나가면 libpd의 대기열(링버퍼)에 들어간다.
- 메인 스레드가 1ms 간격 타이머로 그 대기열을 비우면서 JS 콜백을 부른다. 그래서 콜백은 메인 스레드에서 안전하게 불린다.
- 몇 ms 늦게 온다. 탭이 뒤로 가면 브라우저가 타이머를 늦춰 더 늦다. 게임 이벤트(발소리가 났다, 끝났다)에는 충분하고,
  샘플 단위로 맞춰야 하는 데는 맞지 않는다.
- 대기열 크기가 정해져 있어 넘치면 버려진다. 매 블록마다 보내지 말고 값이 바뀔 때만 보낸다.

## 콜백 등록 (pd4web API)

엔진 객체(`window.Pd4Web`)에 이름과 함수를 넘긴다. **Pd가 보낸 것의 종류마다 함수가 따로 있고, 함수의 인자 개수가 정확해야 한다.**
엔진이 함수의 인자 개수(`함수.length`)를 검사해서, 틀리면 콘솔에 오류만 찍고 등록하지 않는다.
`(...args) =>`처럼 나머지 인자로 쓴 함수는 개수가 0으로 쳐져 거부된다.

| Pd 쪽 (예: `[s foot]`에 들어가는 것) | 등록 함수 | 콜백 모양 | 받는 값 |
| --- | --- | --- | --- |
| `bang` | `onBangReceived` | `(이름) => …` | `"foot"` |
| `0.5` | `onFloatReceived` | `(이름, 값) => …` | `"foot"`, `0.5` |
| `symbol grass` | `onSymbolReceived` | `(이름, 값) => …` | `"foot"`, `"grass"` |
| `1 2 x` (숫자로 시작하는 리스트) | `onListReceived` | `(이름, 값들) => …` | `"foot"`, `[1, 2, "x"]` |
| `step grass 0.5` (글자로 시작하는 메시지) | `onMessageReceived` | `(이름, 선택자, 값들) => …` | `"foot"`, `"step"`, `["grass", 0.5]` |

```js
const pd = window.Pd4Web;
pd.onFloatReceived("foot", (name, value) => console.log(name, value));        // [0.5( → [s foot]
pd.onMessageReceived("foot", (name, selector, values) => {                     // [step grass 0.5( → [s foot]
  if (selector === "step") console.log("발소리", values[0], values[1]);
});
```

종류가 맞지 않으면 오지 않는다. 위처럼 `onMessageReceived`만 등록한 이름에 Pd가 숫자를 보내면 콘솔에
"Callback not found or not a function"만 찍히고 JS에는 아무것도 오지 않는다.

### 같은 이름에 여러 번 등록하면 겹쳐 불린다

등록할 때마다 엔진이 Pd 안에 그 이름을 받는 객체를 하나씩 더 만든다(`libpd_bind`). 보이지 않는 `[r 이름]`이 하나 더 생기는 셈이다.
반면 JS 함수는 이름(과 종류)마다 하나만 기억하고, 다시 등록하면 앞의 것을 덮어쓴다. 지우는 기능은 없다.

그래서 Pd가 한 번 보내면 받는 객체마다 한 번씩, 마지막에 등록한 함수가 여러 번 불린다. 시험 결과:

- `onFloatReceived("b", f1)` 후 `onFloatReceived("b", f2)` → `0.5` 한 번 보내면 **f2가 두 번** 불린다(f1은 안 불림).
- 한 이름에 다섯 종류(bang·float·symbol·list·message)를 다 등록 → 무엇을 보내든 **해당 함수가 다섯 번** 불린다.
- 인자 개수가 틀려 거부된 등록도 받는 객체는 이미 만들어진다(거부되기 전에 만든다).

즉 **이름 하나에 등록은 딱 한 번**이어야 한다. "아무 종류나 받으려고 다섯 종류를 다 등록"하는 방법은 쓸 수 없다.

## 아무거나 보낼 수 있는 하나의 통로 (제안, 아직 안 만듦)

종류가 다섯 갈래로 나뉘고 등록은 한 번만 해야 하므로, **Pd 안에서 모든 것을 리스트 하나로 바꿔** 한 이름으로 받는다.
Pd의 `[list]`(= `[list append]`)는 무엇이 들어오든 리스트로 내보낸다. 시험 결과(`[r to-js] → [list] → [s to-js-out]`, JS는 `onListReceived` 한 번):

| `[s to-js]`에 보낸 것 | JS가 받은 값들 |
| --- | --- |
| `bang` | `[]` |
| `3` | `[3]` |
| `symbol grass` | `["grass"]` |
| `1 2 x` | `[1, 2, "x"]` |
| `step grass 0.5` | `["step", "grass", 0.5]` |
| `done` | `["done"]` |

다섯 종류가 모두 콜백 하나에 한 번씩만 왔다. 글자로 시작하면 첫 값이 메시지 이름이 되어, JS → Pd 쪽 규칙과 같은 모양이다
(`send(bus, ["position", 0.5, 0, 0.5])`는 Pd에서 `position 0.5 0 0.5`).

만든다면:

- Pd 쪽: 패치는 `[s whistle-js]`에 무엇이든 보낸다. 메시지 박스 `[step grass 0.5(`처럼 **첫 단어로 무엇인지 적는 것**을 규칙으로 한다.
  슬롯마다 구별해야 하면 `[s $1-js]`(`slot3-js`)로 보낸다.
- 런타임(`pd-runtime.ts`): 엔진을 열 때 host에 `[r whistle-js] → [list] → [s whistle-js-out]`을 한 번 만들고
  `onListReceived("whistle-js-out", …)`를 한 번 등록한다. 슬롯별 통로는 슬롯을 만들 때 같은 식으로 한 번씩 만든다
  (슬롯은 다시 써도 host의 `[pd slotN]`은 남으므로, 통로도 처음 한 번만).
- 앱 쪽: `engine.on((값들) => …)` 또는 `instance.on((값들) => …)`처럼 값들만 받는 함수 하나. 첫 값으로 무엇인지 나눈다.
