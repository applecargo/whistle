# UWB 장비 연결

앵커를 움직이지 않고 전원만으로 배치를 측정하려면 [무선 앵커 측정](uwb-anchor-survey.md)을 참고하세요. 최초 한 번 펌웨어 설치가 필요합니다.

```text
USB·UDP의 AT+RANGE 또는 UDP의 거리 JSON
  → PC: 거리 검증 → 앵커 좌표로 위치 계산 → 태그별 평활화
  → WebSocket → UWB 페이지 → 기존 지면 판정·3D 표식·Pd
```

PC 수신기는 최대 4개 태그를 각각 계산합니다. 페이지는 선택한 태그 1명의 위치와 소리를 표시합니다.
4명 동시 오디오 분리 출력·ESP32 스피커 전송은 이번 구현 범위에 포함하지 않습니다.
게임 편집기, 플레이어 이동, 지형 렌더링은 기존 동작을 유지합니다.

## 장비 없이 실행

Node.js 22.13 이상에서 프로젝트 폴더를 열고 다음을 실행합니다.

```sh
npm ci
npm run dev
```

다른 터미널에서:

```sh
npm run uwb:demo
```

1. 개발 서버 주소의 `/whistle/uwb-lab/index.html`을 엽니다.
2. `샘플 세계` 또는 `Whistle 3D`를 선택합니다. Whistle 편집기와는 같은 브라우저·서버 주소를 사용합니다.
3. `위치 입력 방식`에서 `실제 데이터 · PC 수신기`를 선택합니다.
4. 수신기 주소 `ws://127.0.0.1:5194`, 태그 ID `0`으로 `연결 / 다시 연결`을 누릅니다.
5. 표식이 움직이면 `오디오 시작`을 누릅니다. 태그 ID `1`, `2`, `3`도 다시 연결해 비교할 수 있습니다.
6. 가상 장비 터미널을 `Ctrl+C`로 종료하면 표식과 소리가 멈춥니다.

가상 장비는 10Hz로 **앵커까지의 거리**를 만들어 실제 UDP 수신 경로에 보냅니다.
페이지에 완성된 좌표를 주입하는 방식이 아니므로 파싱·위치 계산·필터·전송을 함께 시험합니다.
기본 설정은 6×6m 공간, 보드 높이 1.2m 고정입니다. 표시되는 높이는 측정값이 아닌 **고정값**입니다.
기존 `가상 좌표 직접 입력` 모드는 그대로 사용할 수 있으며, 두 모드의 입력은 섞이지 않습니다.

## 앵커 설정

`config/uwb.example.json`을 복사해 실제 설치 위치로 수정하고 `--config`로 지정합니다.
모든 좌표·거리는 미터, `boardHeight`는 현실 바닥 기준 높이입니다.
`x`와 `z`가 바닥 평면이며, 가상공간에서의 플레이어 `y`와는 별개입니다.
`anchors[].boardHeight`는 앵커의 설치 높이입니다. 관객 보드의 높이는 `fixedHeight` 또는 3D 계산 결과를 사용합니다.

| 설정 | 의미 |
| --- | --- |
| `anchors` | 실제 앵커 ID와 X·Z·높이. 3~8개 |
| `tags` | 허용할 태그 ID. 문자열, 최대 4개 |
| `mode: "2d"` | 알려진 `fixedHeight`를 사용해 X·Z 계산. 평면에서 일직선이 아닌 앵커 3개 이상 |
| `mode: "3d"` | X·Z·보드 높이 계산. 같은 평면에 놓이지 않은 앵커 4개 이상 |
| `fixedHeight` | 2D 모드에서 실제 보드를 들 높이. 0~10m |
| `maxResidual` | 계산 위치와 측정 거리 사이 RMS 오차 허용치. 기본 0.35m |
| `smoothingMs` | 지수 평활화 시간 상수. 기본 120ms, 0이면 필터 끔 |

앵커의 높이 차이는 2D 계산에도 반영됩니다. 실제 보드 높이가 고정값과 달라지면 평면 위치에도 오차가 생깁니다.
3D 시험은 예제의 `mode`를 `"3d"`로 바꾸면 됩니다. 예제 앵커는 서로 다른 평면을 구성하며 가상 장비 높이도 움직입니다.
평활화는 태그별로 적용하며, 1초 수신 공백 또는 계산 실패 뒤에는 이전 위치를 끌고 오지 않습니다.
RMS가 작아도 앵커 설치 오차·반사파에 따른 공통 오차를 모두 감지하지는 못하므로 실제 위치와 비교해 보정해야 합니다.

UWB 페이지의 `전시장 매핑` 원점·회전·가로·세로는 이 현실 좌표를 가상 세계에 대응시키는 별도 설정입니다.
센서 좌표계와 매핑의 미터 기준을 맞추세요. 기본 설정끼리는 6×6m로 일치합니다.

## 실제 장비: USB부터 연결

앵커 배치 좌표를 측정하기 전에는 거리만 확인할 수 있습니다.

```sh
npm run uwb:bridge -- --serial /dev/cu.wchusbserial110 --baud 115200 --ranges-only
```

포트와 속도는 연결된 보드에 맞춥니다. 현재 시험한 태그는 115200 baud이며, 제조사 원본 예제는 250000 baud입니다.
UWB 페이지에서 `실제 데이터 · PC 수신기`를 선택하고 태그 ID `0`으로 연결하면 앵커별 거리(m)를 표시합니다.
이 모드에서는 PC가 좌표를 계산하지 않고 원본 거리만 페이지로 전달합니다. 페이지에서 배치를 적용하기 전에는 위치 표식과 오디오가 비활성화됩니다.
현재 보고에서 빠진 앵커는 `미수신`으로 표시하고, 1초간 새 보고가 없으면 거리 표시를 지웁니다.
앵커를 같은 높이에 놓아도 시험할 수 있습니다. 줄자로 비교할 때는 바닥상의 거리가 아닌 태그 안테나와 앵커 안테나 사이의 직선거리를 측정합니다.

### 페이지에서 직사각형 배치 설정

- 배치: A0 왼쪽 위 → A1 오른쪽 위 → A2 오른쪽 아래 → A3 왼쪽 아래
- `실제 앵커 배치`에 가로·세로·앵커 공통 높이·태그 높이를 미터로 입력
- `배치 적용 · 위치 연결` → 새 거리로 평면 위치 계산 → `오디오 시작`
- 적용 시 전시장 매핑은 원점 (0,0), 회전 0°, 입력한 가로·세로로 설정
- 태그 높이는 고정값이며 이동 중 유지. 가상 지면 높이와 별도로 Pd에 전달
- 계산 실패·수신 중단·범위 밖에서는 음소거. 거리 표는 계산 실패 시에도 확인 가능
- 입력 수정은 적용 버튼을 눌러 반영. 배치 재적용 시 과거 위치·평활화 상태 초기화
- `거리만 확인`으로 돌아가면 위치·사운드 연결 해제. 페이지 새로고침 시 배치 재입력

이 경로는 기존 PC 좌표 계산기를 브라우저에서 재사용합니다. 브릿지는 계속 `--ranges-only`로 실행합니다.
PC에서 좌표를 계산하는 기존 모드는 아래 설정 파일 방식을 사용합니다.

### 중앙 기준 임시 거리 보정

- 실제 배치를 적용한 뒤 태그를 사각형 정중앙·입력한 높이에 고정
- `중앙 거리 보정 · 5초`: 앵커별 원본 거리의 중앙값과 배치상 예상 거리 차이를 계산
- 원본은 유지하고, 위치 계산에만 앵커별 차이를 빼서 사용. 원본·보정 거리를 표에서 비교
- 표본 부족·큰 변동·비정상 보정 거리는 거부. 보정 후에도 범위 밖·수신 중단 시 음소거
- `거리 보정 해제`로 복귀. 배치 재적용·페이지 새로고침 시 해제하며 다른 태그에는 적용하지 않음
- 한 지점에서 얻은 임시 보정이므로 다른 위치·안테나 방향에서도 실측 비교 필요. 장비의 안테나 지연 설정은 변경하지 않음

제조사 안테나 지연 보정 절차: https://www.makerfabs.com/blog/post/mauwb-accuracy-antenna-delay-calibration

```sh
npm run uwb:bridge -- --list-ports
npm run uwb:bridge -- --serial /dev/cu.usbmodemXXXX --config config/uwb.example.json
```

Windows에서는 경로 대신 `COM3`처럼 목록에 표시되는 포트를 사용합니다. 기본 속도는 115200이며 `--baud`로 변경할 수 있습니다.
Arduino Serial Monitor처럼 같은 포트를 열고 있는 프로그램은 종료합니다.
수신기는 보드를 읽기만 하며, 펌웨어 업로드·태그/앵커 역할 설정·AT 명령 전송을 대신하지 않습니다.
USB 연결이 끊기면 장비를 확인한 뒤 수신기를 다시 실행하고 페이지에서 다시 연결합니다.

기본 `--format makerfabs`는 MaUWB ESP32S3의 다음 원본 AT 보고를 지원합니다.

```text
AT+RANGE=tid:0,mask:07,seq:42,range:(150,200,350,0,0,0,0,0),rssi:(-70,-75,-80,0,0,0,0,0)
AT+RANGE=tid:0,mask:07,seq:43,range:(150,200,350,0,0,0,0,0),ancid:(3,1,2,-1,-1,-1,-1,-1)
```

위 숫자는 형식 예시입니다. 실제 앵커 설정과 일치하는 거리를 보내야 좌표가 계산됩니다.
`mask`의 유효한 항목만 사용하고 cm를 m로 바꿉니다. `ancid`가 있으면 배열 순서 대신 실제 앵커 ID를 사용합니다.
구형 보고처럼 `ancid`가 없으면 배열 0~7을 앵커 ID로 사용합니다. RSSI는 위치 계산에 사용하지 않습니다.
부팅 로그·OK 응답은 무시합니다. 한 줄이 완성될 때까지 기다리며 너무 긴 줄은 버립니다.
제조사의 `get_range` 예제가 변환한 `{"id":0,"range":[...]}` 형식은 지원하지 않습니다. 원본 AT 보고를 출력하는 태그 예제 또는 아래 표준 JSON을 사용합니다.

참고한 제조사 자료:
- [태그의 원본 UART 출력 예제](https://github.com/Makerfabs/MaUWB_ESP32S3-with-STM32-AT-Command/blob/main/example/esp32s3_at_t0/esp32s3_at_t0.ino)
- [AT 명령 매뉴얼 v1.1.2](https://github.com/Makerfabs/MaUWB_ESP32S3-with-STM32-AT-Command/blob/main/example/Firmware%20V1.1.6%20Manual%26%20Demo/Makerfabs%20UWB%20AT%20Module%20AT%20Command%20Manual(v1.1.2).pdf)

현재 T0는 115200 baud에서 Makerfabs 원본 거리 보고를 출력합니다.

## T0 무선 연결

T0의 ESP32가 STM32 UART에서 받은 `AT+RANGE=...` 한 줄을 줄바꿈까지 그대로 UDP 한 패킷으로 보냅니다. Mac 수신기가 USB와 같은 파서로 cm를 m로 변환하고 기존 앵커 배치로 위치를 계산합니다.

1. Mac과 보드를 같은 공유기에 연결합니다. `config/uwb-router.local.json`에 기존 앵커와 같은 공유기 설정을 사용합니다.
2. 아래에서 Mac의 Wi-Fi IP로 태그 접속 파일을 생성합니다. Mac의 IP가 바뀌면 새 IP로 다시 생성·설치하거나 공유기에서 DHCP 주소를 예약합니다.
3. Arduino ESP32S3 Dev Module로 `firmware/uwb-tag/uwb-tag.ino`를 T0의 UART USB를 통해 설치합니다. 기존 STM32의 태그 ID·PAN 설정을 사용합니다.
4. Mac에서 해당 네트워크 주소로 수신기를 실행합니다. 아래 IP는 예시입니다. `config/uwb.example.json`을 복사해 현장에서 측정한 앵커 좌표로 수정하고, 수신기에 그 파일의 경로를 지정합니다.

```sh
node --experimental-strip-types scripts/uwb-setup-tag.ts --host 172.30.1.28
npm run uwb:bridge -- --udp-host 172.30.1.28 --config /path/to/venue.json
```

전원만 공급하면 T0 OLED에 태그 IP와 목적지, 전송한 패킷 수가 표시됩니다. UWB 페이지의 수신기 주소는 계속 `ws://127.0.0.1:5194`, 태그 ID는 `0`입니다.

## 현장 높이 시험

2026-11-18 실물 시험에서 T0는 별도 전원으로 공유기에 다시 접속했습니다. Mac은 원본 거리로 X·Z를 계산했고, 브라우저에서 위치별 오디오를 실행했습니다. 이때 2D 수신기는 A0·A1·A2와 고정 높이 0.65m를 사용했습니다.

| 첫 3D 시험 | 결과 |
| --- | --- |
| 안테나 높이 | A0·A1·A2 약 0.65m, A3 약 1.20m, T0 약 0.65m에 고정 |
| 15초간 수신 | 1,500건 중 네 앵커 거리가 모두 있는 보고 1,493건, 유효한 3D 높이 0건 |
| A1–A3 검산 | 임시 배치상 직선거리 4.90m. T0를 경유한 두 측정 거리의 합은 중앙값 4.02m, 최대 4.27m |

T0를 거친 거리의 합은 앵커 간 직선거리 이상이어야 합니다. 임시 배치와 거리 보고가 이 조건을 만족하지 않아 정지 중 높이 흔들림은 평가할 수 없었습니다.

1. 전시장에서 각 안테나 중심의 바닥 기준 높이와 바닥에 투영한 X·Z를 측정합니다. 특히 A1–A3 바닥 간격을 줄자로 확인하고, 높이 차이를 반영한 직선거리와 T0 경유 거리의 합을 비교합니다.
2. A0·A1·A2가 같은 높이라면 A3를 다른 높이에 두고, 실측한 네 좌표를 수신기 설정에 입력해 `mode`를 `"3d"`로 실행합니다. 페이지에서 태그 ID `0`으로 연결해 높이 출처가 UWB인지 확인합니다.
3. 같은 바닥 위치와 방향에서 T0를 두 높이(예: 0.65m와 1.40m)에 각각 15초 고정합니다. 유효 높이 비율, 높이 중앙값의 차이, 정지 중 10~90백분위 범위를 비교합니다.
4. 높이 변화를 구분할 수 있으면 Pd 입력 `whistle-board-height`를 원하는 음색 파라미터에 연결합니다. 현재 패치는 높이값 수신까지만 구현합니다.

## 다른 송신기의 UDP JSON 형식

시뮬레이터나 JSON 형식을 쓰는 다른 송신기는 아래 패킷을 같은 네트워크의 PC UDP 5195로 보낼 수 있습니다. 실물 T0는 위의 원본 텍스트 형식을 사용합니다.
PC가 외부 UDP를 받게 하려면 명시적으로 실행합니다.

```sh
npm run uwb:bridge -- --udp-host 0.0.0.0 --config config/uwb.example.json
```

JSON 송신기는 UDP 한 데이터그램에 하나의 UTF-8 JSON 객체를 보냅니다. 최대 4096바이트입니다.
USB로 같은 형식을 보낼 때는 `--serial PORT --format json`을 쓰고 객체마다 줄바꿈합니다.

```json
{
  "type": "ranges",
  "tagId": "0",
  "seq": 42,
  "ranges": [
    { "anchorId": "0", "distance": 3.419064199455752 },
    { "anchorId": "1", "distance": 5.974110812497538 },
    { "anchorId": "2", "distance": 5.974110812497538 },
    { "anchorId": "3", "distance": 3.2388269481403297 }
  ]
}
```

거리값은 한 측정 주기의 동일 태그 거리 묶음이어야 합니다. 서로 다른 시점의 오래된 거리를 합치지 마세요.
ID는 문자열, `seq`는 태그별로 증가하는 0 이상의 정수입니다. 활성 추적 중 중복·역순 패킷은 무시합니다.
장비가 재시작해 카운터가 초기화되면 1초 수신 공백 뒤 새 시퀀스를 받아들입니다.
Makerfabs 원본 USB 보고는 직렬 순서를 사용하므로 카운터 순환을 허용하고 연속 중복은 무시합니다.
센서 타임스탬프의 절대 시각은 사용하지 않고 PC 도착 시각으로 관리합니다.
서로 다른 송신기가 동일 태그를 동시에 보내지 않도록 구성합니다.

WebSocket은 PC의 `127.0.0.1:5194`에서만 열리므로 페이지도 같은 PC의 localhost 개발 서버에서 사용합니다.
공개 배포 페이지의 원격 접속은 지원하지 않습니다. UDP 기본 바인딩도 localhost이며 외부 장비 연결 시에만 변경합니다.
포트 충돌은 `--ws-port`, `--udp-port`로 변경하고 페이지의 수신기 주소도 맞춥니다.

## 수신 중단과 사운드

페이지는 선택한 태그의 신규 좌표만 사용합니다. PC가 좌표 계산 실패를 보고하면 마지막 유효 위치를 최대 120ms 유지한 뒤 음소거합니다. 1초간 수신이 없거나 연결이 종료되면 표식과 소리를 끕니다.
정상 데이터가 돌아오면 이미 켜 둔 오디오만 재개합니다. `오디오 종료` 뒤에는 데이터가 도착해도 시작하지 않습니다.
새 연결에 과거 좌표를 재전송하지 않습니다. 연결 실패는 주소·PC 프로그램을 확인하고 `다시 연결`합니다.
직접 입력 모드에는 시간 초과 판정이 없습니다.

보드 높이는 pd4web의 `player.pd`에 `whistle-board-height`로 전달합니다. 표식과 가상 발 높이는 지면을 따릅니다.
풀 타격과 고리 숨결은 게임과 같은 `world-audio.pd`에서 재생합니다. 가상·실제 태그는 모두 매핑된 X·Z로 음원까지의 거리와 좌우 방향을 계산합니다. [공간화와 Pd 입력](soundscape-design.md)
